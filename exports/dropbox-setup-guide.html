Changing the Dropbox Account

A complete, step-by-step guide to pointing the screenshot pipeline at a different Dropbox account or app — what to collect from Dropbox, and how to hand it over securely.

0  Background: what the system needs

The screenshot pipeline authenticates to Dropbox with three values (all read from the environment):

ValueSensitive?What it's for
DROPBOX_APP_KEYNo — public client IDIdentifies your Dropbox app
DROPBOX_APP_SECRETYesProves the app is really yours
DROPBOX_REFRESH_TOKENYesLong-lived, auto-renewing key that mints short-lived access tokens forever
There is also an optional DROPBOX_ACCESS_TOKEN — ignore it. That is the 4-hour token from the console button; it expires and causes outages. The refresh token is what makes uploads work permanently with no manual re-auth.
Before you switch: screenshots already uploaded to the old account stay there and will no longer be viewable in the app (the app looks them up in whatever account the new token points to). New screenshots go to the new account. Only switch if that is acceptable.

1  In Dropbox: create / open the app

  1. Go to https://www.dropbox.com/developers/apps and sign in with the Dropbox account you want screenshots stored in — this is the account that matters.
  2. Click Create app (or open an existing app to reuse it).
  3. Choose:
    • Scoped access (the only modern option).
    • Access type: Full Dropbox (recommended — lets the app write to /ActiveTrackScreenshots/...). If you pick App folder, screenshots land inside the app's private folder instead — also fine, but the path is relative to that folder.
  4. Name the app (e.g. ActiveTrack-Screenshots) and click Create app.

2  Set permissions (scopes) — do this BEFORE making a token

Open the Permissions tab, tick all of these, then click Submit:

  • account_info.read
  • files.metadata.read
  • files.content.read
  • files.content.write
  • sharing.read
  • sharing.write
Critical: if you generate a token first and change scopes later, the old token will not have the new permissions. Always set scopes before generating the refresh token. If you change scopes afterward, regenerate the refresh token (repeat Step 4).

3  Get the App key and App secret

On the Settings tab:

  • App key → this is DROPBOX_APP_KEY.
  • App secret → click Show; this is DROPBOX_APP_SECRET.

4  Get the refresh token (the easy-to-get-wrong step)

The console's “Generate access token” button gives only a 4-hour token — do not use it. The permanent refresh token comes from a one-time OAuth “offline” authorization.
  1. Build this URL, replacing YOUR_APP_KEY: 
    https://www.dropbox.com/oauth2/authorize?client_id=YOUR_APP_KEY&token_access_type=offline&response_type=code
  2. Open it in your browser, choose the correct account, click Allow.
  3. Dropbox shows a short authorization code (a random string — not an sl.u... value). Copy it. It expires within a few minutes, so use it promptly.
  4. Exchange that code for a refresh token — two ways:

Option A — I do it for you (recommended)

Put the app key + secret into Secrets first (Step 5), then send me the code. I run the exchange and drop the refresh token into a temp file you copy into Secrets.

Option B — you do it yourself in the Replit Shell (most private)

APP_KEY='paste_app_key'
APP_SECRET='paste_app_secret'
CODE='paste_authorization_code'
curl -s https://api.dropboxapi.com/oauth2/token \
  -d grant_type=authorization_code \
  -d code="$CODE" \
  -u "$APP_KEY:$APP_SECRET"

The JSON response includes "refresh_token": "..." — that is your DROPBOX_REFRESH_TOKEN.

5  What you give me, and how (securely)

Put these into the Secrets pane (Tools → Secrets / the lock icon) — never the .replit file, and never paste the secret or refresh token into chat:

Secret keyWhere it comes from
DROPBOX_APP_KEYStep 3 (fine to paste in chat too — it's public)
DROPBOX_APP_SECRETStep 3
DROPBOX_REFRESH_TOKENStep 4 — if I generated it, run cat /tmp/.dbx_rt in the Shell and paste the output into the Secret
The only things safe to send me in chat are the app key (public) and the one-time authorization code (short-lived, useless on its own).

6  What I do after your Secrets are saved

  1. Delete the old plaintext DROPBOX_* entries from .replit (all [userenv.*] sections) so no credentials sit in the repo.
  2. Drop the unused DROPBOX_ACCESS_TOKEN.
  3. Restart the API server so it picks up the new Secrets.
  4. Verify end-to-end: confirm a screenshot uploads and lands under /ActiveTrackScreenshots/{label}_{region}_{group}/... in the new account.

Quick checklist (short version)

  1. Dropbox → create/open app → Full Dropbox, Scoped.
  2. Permissions tab → enable the 6 scopes → Submit.
  3. Settings → copy App key + App secret.
  4. Authorize with the token_access_type=offline URL → copy the code → exchange → get refresh token.
  5. Save DROPBOX_APP_KEY, DROPBOX_APP_SECRET, DROPBOX_REFRESH_TOKEN in Secrets.
  6. Tell me → I clean .replit, restart, and verify.

Security note: credentials belong only in the encrypted Secrets store, never in .replit (which is committed to git). If a secret ever lands in .replit, deleting it is not enough — it stays in git history, so it must be rotated at the source in the Dropbox App Console.
