# System Overview

The application receives screenshots/images from multiple desktop agents.

Instead of storing these images permanently on the server, they should be uploaded to Dropbox.

After a successful upload:

1. Store the Dropbox public URL in the database.
2. Delete the local image from the server.
3. Keep only the Dropbox URL for future access.

Each agent device should have its own folder inside Dropbox.

Example:

```
Dropbox
│
└── AgentImages
    │
    ├── Dell-68
    │      image1.jpg
    │      image2.jpg
    │
    ├── HP-Office
    │      image1.jpg
    │
    ├── Lenovo-12
    │      image1.jpg
    │
    └── MacBook-Pro
```

The folder name must be created using the agent device label that already exists in the authentication token.

Example:

```
Device Label:

Dell-68

Dropbox Folder:

AgentImages/Dell-68/
```

If the folder does not exist, automatically create it.

If it already exists, simply upload the image into that folder.

# Image Upload Workflow

Implement the following workflow.

## Step 1

The desktop agent sends an image to the backend.

The backend stores it temporarily.

---

## Step 2

Read the device label from the authenticated token.

Example:

```
Dell-68
```

---

## Step 3

Check whether the Dropbox folder exists.

Example:

```
AgentImages/Dell-68
```

If it does not exist:

* Create the folder.

If it exists:

* Continue.

---

## Step 4

Upload the image to Dropbox.

Generate a unique filename.

Example:

```
2026-07-06_10-35-12.jpg

or

uuid.jpg
```

Avoid filename collisions.

---

## Step 5

Generate a public Dropbox URL for the uploaded image.

The application must be able to access the image later using this URL.

If Dropbox returns a share link, convert it into a direct-access link if required.

---

## Step 6

Save only the Dropbox image URL in the database.

Example:

```
Screenshot
--------------------------------------------
id

employee_id

dropbox_url

created_at
```

Do not save the local file path.

---

## Step 7

Verify that:

* upload completed successfully
* URL is generated successfully
* database updated successfully

Only after all three succeed:

Delete the local image from the server.

If any step fails:

* do NOT delete the local image
* log the error
* retry later if appropriate

# Random Upload Logic

The desktop agent continuously captures screenshots.

These screenshots must **not** be uploaded immediately.

Instead:

For every device independently,

Upload screenshots randomly within a rolling 5-hour window.

Requirements:

* Every device has its own upload schedule.
* Upload times must appear random.
* Avoid all devices uploading simultaneously.
* Preserve screenshot order where required.
* Ensure no screenshots are skipped.
* Handle server restarts gracefully.
* Handle pending uploads after downtime.
* Prevent duplicate uploads.
* Prevent race conditions.

Explain the scheduling algorithm before implementing it.
