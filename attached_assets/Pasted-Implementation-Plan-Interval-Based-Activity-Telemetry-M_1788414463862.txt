Implementation Plan: Interval-Based Activity Telemetry Migration
Goal Description
Perform a staged telemetry migration across the API, PostgreSQL database, Python agent, and Node agent. The goal is to record exact timestamped state transitions (intervals) rather than aggregated duration snapshots. This fundamentally changes how Active, Passive, Total, Productive, and Break Time are calculated, ensuring ActivTrak/TimeDoctor-level accuracy.

Telemetry Contract & Definitions
Separation of States
The stored payload will explicitly separate states:

json

{
  "engagementState": "active",
  "sessionState": "unlocked",
  "connectivityState": "offline"
}
engagementState: active, passive, idle
sessionState: unlocked, locked, suspended, monitoring_paused
connectivityState: online, offline, unknown
Network offline is not a time category. Activity recorded while disconnected is still processed normally after upload.

Break Time Definition
Break Time = union of qualifying idle intervals.

Excludes: Locked time, Suspended time, Monitoring-paused time, Unexplained telemetry gaps.
(Optional future extension: configurable breakAfterSeconds if brief idle periods should not count as breaks).
Configuration & Dynamic Thresholds
Thresholds for Passive and Idle time will be dynamically provided by the server via the configuration/heartbeat response and cached locally for offline use:

json

{
  "passiveAfterSeconds": 120,
  "idleAfterSeconds": 300
}
Every uploaded interval will include the policy version/thresholds used at the time of recording.

Proposed Changes
Phase 1: Contract, API, and Compatibility
API Payload & Acknowledgement: Introduce the new batch payload format. The API will respond with explicit ACKs:
json

{
  "batchId": "uuid",
  "acceptedSegmentIds": ["uuid-1"],
  "rejected": [ { "segmentId": "uuid-2", "code": "INVALID_INTERVAL" } ]
}
Database Uniqueness Guarantees (PostgreSQL / Drizzle):
UNIQUE(device_id, segment_id)
UNIQUE(device_id, sequence_namespace, sequence)
Classification Preservation: Store the productivity category, classification rule/policy version, engagement state, and session state independently at ingestion time.
Strict Server Validation: Enforce endedAt > startedAt, positive safe durations, valid states, monotonic duration agreement, URL length limits, and correct segment/batch IDs.
Phase 2: Python Interval Journal
Shared Module: Create telemetry/interval_journal.py, telemetry/activity_state.py, telemetry/durable_queue.py, and telemetry/clock.py.
Durable Queue & Crash Recovery: Use a local SQLite journal. Recover open intervals conservatively at the last trustworthy observation.
Privacy First: Normalize hostnames, remove fragments/credentials/sensitive queries, and apply limits to URLs before writing to the local durable queue.
Exact Windows Input: Ensure keyboard events are natively captured to fix idle attribution.
Phase 3: Shadow Reporting Calculations
Calculate duration strictly from interval bounds and union overlapping intervals.
Metrics: Formally calculate Productive Active, Productive Passive, Unproductive Active, Unproductive Passive, Undefined Active, Undefined Passive.
Legacy Support: Do not change the production report calculations before the new telemetry has been collected and compared in shadow mode.
Phase 4: Node Parity
Implement the exact same interval contract in agent-node/.
Remove reliance on cursor movement to accurately detect keyboard-only input on Windows.
Phase 5: Controlled Installer Rollout & Report Cutover
Release behind a telemetry-version flag. Compare daily differences and cut over only when metrics stabilize.
